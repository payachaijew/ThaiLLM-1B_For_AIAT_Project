# แผน Compute + Storage (rented GPU, ไม่รอ LANTA)

**วันที่:** 2026-08-18 · rev.1
**ข้อจำกัดใหม่:** เป้าข้อมูล **6–10B tokens** · LANTA อนุมัติช้า → **เช่า GPU** · ต้องวางแผนที่เก็บข้อมูล

---

## 1. งบ token 6–10B แปลว่าอะไร

| | ค่า |
|---|---|
| เป้า total tokens | **6–10B** |
| ไทย 50% | **3–5B Thai tokens** |
| SEA-PILE-v2 th ภายใต้ Qwen tokenizer | **~10B tokens** (6.5B × 1.541) |
| ต้องใช้กี่ epoch | **0.3–0.5 epoch** |

✅ **SEA-PILE-v2 ตัวเดียวพอ ไม่ต้องแตะ Mangosteen หรือ ThaiLLM Repo เลย** และไม่ต้องวนข้อมูลซ้ำ

---

## 2. เวลาและค่าใช้จ่าย (Qwen3-1.7B)

```
FLOPs ≈ 6 × 1.7e9 × D
A100 80GB @ MFU 0.40 ≈ 125 TFLOPS ; H100 @ MFU 0.40 ≈ 395 TFLOPS
```

| การ์ด | 6B tokens | 10B tokens | ค่าเช่าโดยประมาณ* |
|---|---|---|---|
| 1×A100 | ~5.7 วัน | ~9.5 วัน | ❌ ช้าเกิน |
| **4×A100** | **~34 ชม.** | **~57 ชม.** | **~$250–450** |
| 2×H100 | ~22 ชม. | ~36 ชม. | ~$180–320 |
| 8×A100 | ~17 ชม. | ~28 ชม. | ~$250–450 |

\* ราคาตลาด spot/community ราว $1.5–2.5/GPU-hr — **ต้องเช็คจริงตอนจอง**

**+ ablation 3 arms × 1–2B tokens ≈ เพิ่มอีก ~$100–200**

→ **งบรวมทั้งโครงการประมาณ $400–700** ซึ่งอยู่ในวิสัยที่ขอได้

## 3. ⚠️ ปัญหาใหม่ที่ใหญ่ที่สุดของการเช่า GPU: **storage เป็นของชั่วคราว**

เครื่องเช่าดับ = **ข้อมูลหายหมด** ต้องแยกให้ชัดว่าอะไรอยู่ตรงไหน

### สามชั้นของที่เก็บ

| ชั้น | เก็บอะไร | ที่ไหน | ขนาด |
|---|---|---|---|
| **1. ต้นฉบับถาวร** | corpus ที่ clean แล้ว + manifest + hash | **HF private dataset repo** | ~16 GB |
| **2. working copy** | ข้อมูลที่ tokenize แล้ว | NVMe ของเครื่องเช่า (โหลดใหม่ทุกครั้ง) | ~40 GB |
| **3. checkpoint** | โมเดลระหว่างเทรน | **HF private model repo** | 20–27 GB/ชิ้น |

### ประมาณการพื้นที่

| รายการ | ขนาด |
|---|---|
| SEA-PILE th ดิบ (54 shards) | 22.2 GB |
| หลัง clean (ตัด dup 5.7% + สั้น + spam ≈ 25–30%) | **~16 GB** |
| tokenized (uint32, vocab 151,936 → 4 bytes/token) | **~40 GB** ต่อ 10B tokens |
| replay อังกฤษ/code/math | ~20 GB |
| checkpoint 1 ชิ้น (weights + AdamW states) | **~20–27 GB** |
| เก็บ 5 checkpoints | ~135 GB |
| **รวมบนเครื่องเช่า** | **~250 GB** |

→ **จองเครื่องที่มี NVMe อย่างน้อย 500 GB**

### ทำไมแนะนำ HF private repo เป็นต้นฉบับ
- ฟรี มี versioning มี hash ในตัว
- `huggingface_hub` อยู่ใน stack เราอยู่แล้ว
- ดึงกลับได้จากเครื่องเช่าเครื่องไหนก็ได้
- **ถ้าไม่อยากใช้ HF** → Cloudflare R2 (ไม่มีค่า egress) หรือ Backblaze B2

### ❗ กฎเหล็กของการเช่า GPU
1. **checkpoint ทุก ~1000 steps และ push ขึ้น durable storage ทันที** ไม่ใช่ตอนจบ
2. **ห้ามเก็บของชิ้นเดียวไว้บนเครื่องเช่า** ถ้าไม่มีสำเนาที่อื่น
3. เขียนสคริปต์ setup ให้ rebuild เครื่องได้จากศูนย์ภายใน 30 นาที

## 4. ลำดับงานที่ปรับใหม่

| Phase | งาน | ที่ไหน | เวลา |
|---|---|---|---|
| **0** (เกือบเสร็จ) | eval suite + held-out + baseline | เครื่องตัวเอง | เหลือ decontamination |
| **1** | โหลด 54 shards → clean → dedup → filter | **เครื่องตัวเอง / VPS ถูก ๆ** (ไม่ต้องใช้ GPU) | 2–4 วัน |
| **1.5** | push corpus ที่ clean แล้วขึ้น HF private | — | ครึ่งวัน |
| **2** | เช่า GPU → preflight → **ablation 3 arms** | เครื่องเช่า | ~1 วัน |
| **3** | CPT รอบหลัก 6–10B tokens | เครื่องเช่า | 1.5–2.5 วัน |
| **4** | eval + เขียน model paper | เครื่องตัวเอง | — |

💡 **Phase 1 ทำบนเครื่องตัวเองได้ทั้งหมด** — เป็นงาน CPU/disk ล้วน **จึงไม่ต้องจ่ายค่าเช่า GPU ระหว่างทำความสะอาดข้อมูล** ซึ่งเป็นส่วนที่กินเวลานานที่สุด

**เช่า GPU เฉพาะ Phase 2–3 = ~3 วัน** เท่านั้น

## 5. ความเสี่ยงเฉพาะของการเช่า

| ความเสี่ยง | รับมือ |
|---|---|
| เครื่องโดนยึดกลางคัน (spot) | checkpoint ถี่ + push ทันที + resume ได้ |
| ข้อมูลหายตอนเครื่องดับ | ต้นฉบับอยู่ HF ไม่ใช่บนเครื่อง |
| โหลด corpus ใหม่ทุกครั้งเสียเวลา | เก็บ tokenized เป็นไฟล์เดียวใหญ่ ๆ |
| ค่าใช้จ่ายบานปลาย | ตั้ง budget alert + จบ ablation ก่อนค่อยรันหลัก |
