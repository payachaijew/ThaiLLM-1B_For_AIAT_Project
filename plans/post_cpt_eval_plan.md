# แผนการวัดผลหลัง CPT — สิ่งที่ชุด 7 งานเดิมวัดไม่ได้

**สร้างเมื่อ:** 2026-08-23 · ยังไม่ตัดสินใจ รอทีมพิจารณา
**สถานะ:** ร่าง — ต้อง freeze ก่อน CPT รอบหลักจบ

---

## ทำไมต้องตัดสินก่อน ไม่ใช่หลัง

สามเหตุผล เรียงจากสำคัญที่สุด

**1. หลักการเดียวกับที่เรา freeze ชุด 7 งานไว้ตั้งแต่ต้น**

ถ้ารอให้ CPT เสร็จแล้วค่อยเลือกว่าจะวัดอะไร เราจะเลือกตัวชี้วัดที่โมเดลเราทำได้ดีโดยไม่รู้ตัว
`THAILLM-EVAL-FROZEN-V1` ปิดผนึกด้วย sha256 ก่อนเห็นผลใด ๆ ด้วยเหตุผลนี้
**ชุดวัด generation ต้องปิดผนึกแบบเดียวกัน**

**2. chat template ต้องตัดสินก่อน SFT และมันผูกกับวิธีวัด**

ถ้าเปลี่ยน template ทีหลัง ต้อง SFT ใหม่ทั้งหมด และ prompt ในชุดวัดผลต้องเขียนใหม่ตาม

**3. ของบางอย่างต้องใช้เวลาสร้าง**

ชุด IFEval ภาษาไทยไม่มีสำเร็จรูป ต้องสร้าง 200–300 ข้อ ทำระหว่างที่ CPT รันอยู่ได้
ถ้ารอจนเทรนเสร็จค่อยเริ่ม จะเสียเวลาเปล่าไปหลายวัน

---

## สิ่งที่ชุดเดิมวัดได้ และวัดไม่ได้

| | ชุด 7 งานที่ freeze ไว้ |
|---|---|
| ✅ วัดได้ | ความรู้ · ความเข้าใจภาษา · ตอบข้อสอบช้อยส์ · BPB |
| ❌ วัดไม่ได้ | ทำตามคำสั่งไหม · เขียนไทยรู้เรื่องไหม · ตอบเป็นภาษาอะไร · คุยต่อเนื่องได้ไหม · ปลอดภัยไหม |

หลัง SFT ต้อง **รันชุดเดิมซ้ำด้วย** เพื่อเช็คว่า SFT ไม่ได้ทำความรู้พัง — ไม่ใช่แทนที่

---

## ตัวชี้วัดที่เสนอให้เพิ่ม

### 1. อัตราการตอบเป็นภาษาไทย — ทำก่อนเป็นอันดับแรก

**ทำไมสำคัญที่สุด:** failure mode ที่พบบ่อยที่สุดของโมเดลที่ CPT ภาษาใหม่คือ
**ถามไทยแล้วตอบอังกฤษ** หรือปนกันกลางประโยค เพราะ base model เดิมถนัดอังกฤษกว่ามาก
ถ้าโมเดลตอบอังกฤษ 40% ของเวลา มันก็ไม่ใช่ ThaiLLM ไม่ว่าคะแนนอื่นจะสวยแค่ไหน

**วิธีวัด:** นับสัดส่วนอักษรไทยในคำตอบ เทียบกับ prompt ที่เป็นไทยล้วน
เขียนสคริปต์เองได้ **ไม่ต้องพึ่งโมเดลตัดสิน ไม่มีปัญหาสัญญาอนุญาต ไม่มีความเห็นส่วนตัว**

**ต้นทุน:** ต่ำสุดในบรรดาทุกข้อ · **คุ้มค่าที่สุด**

### 2. การทำตามคำสั่งแบบตรวจได้ด้วยโค้ด (IFEval-style)

คำสั่งที่มีเงื่อนไขตรวจได้ด้วยโปรแกรม เช่น

- "ตอบเป็น 3 ข้อ" → นับ bullet
- "ห้ามใช้คำว่า X" → ค้นสตริง
- "ตอบไม่เกิน 50 คำ" → นับคำ
- "ขึ้นต้นด้วยคำว่า Y" → เทียบ prefix

**ข้อดี:** ตรวจได้แน่นอน ไม่ต้องมีคนหรือโมเดลมาให้คะแนน ทำซ้ำได้ 100%

**ต้องทำ:** สร้างชุดภาษาไทย 200–300 ข้อ ทำระหว่าง CPT รันได้

### 3. คุณภาพการเขียน — ต้องใช้ผู้ตัดสิน

⚠️ **กับดักสัญญาอนุญาตซ้ำรอยเดิม**

**สัญญาอนุญาตของโมเดลผู้ตัดสิน ติดมากับผลลัพธ์ที่มันตัดสิน** เหมือนกรณีข้อมูล SFT
ถ้าใช้ GPT-4 ตัดสิน ผลที่ได้ติด ToS ของ OpenAI ซึ่งอาจกระทบการเผยแพร่

**ทางที่ปลอดภัย:** ใช้ Qwen เป็นผู้ตัดสิน — อยู่ในข้อยกเว้นเดียวกับที่เราใช้ข้อมูล SFT
(ดู `SFT_DATA_LICENSE_AUDIT.md` ข้อ 1)

### 4. บทสนทนาหลายเทิร์น

ถามต่อเนื่อง 3–4 เทิร์น ดูว่ายังจำบริบทได้ไหม ยังตอบเป็นไทยอยู่ไหม
โมเดลเล็กมักหลุดบริบทตั้งแต่เทิร์นที่สอง

### 5. ความปลอดภัยและการปฏิเสธ

ชุด prompt ภาษาไทยที่ควรถูกปฏิเสธ **ต้องทำก่อนปล่อยสาธารณะ**
model card ต้องรายงานผลตรง ๆ ไม่ว่าจะออกมาอย่างไร

### 6. loss บนชุด held-out ของ SFT

มีอยู่แล้วจาก `sft/build_sft.py` ใช้เช็ค overfitting ระหว่าง SFT

## ของที่ควรไปตรวจว่ามีให้ใช้แล้วหรือยัง

**SEA-HELM (เดิมชื่อ BHASA)** — ครอบคลุมภาษาไทยและมีส่วนวัด instruction following
ถ้าเวอร์ชันปัจจุบันใช้ได้ จะประหยัดเวลาสร้างชุดเองไปมาก

**ยังไม่ได้ตรวจว่าครอบคลุมแค่ไหนและสัญญาอนุญาตเป็นอย่างไร** — ต้องตรวจก่อนตัดสินใจ

---

## ของถูกที่สุดที่จับสิ่งที่ metric มองไม่เห็น

**ให้คนไทยจริง 3 คน ลองใช้คำถาม 50 ข้อ แล้วให้คะแนน**

ใช้เวลาคนละชั่วโมง ไม่มีค่าใช้จ่าย และมักจับปัญหาที่ตัวเลขทุกตัวมองข้าม เช่น
ตอบถูกแต่ภาษาแข็งจนอ่านไม่รู้เรื่อง หรือใช้คำที่คนไทยไม่พูดกัน

| # | เรื่อง | ต้องตัดสินเมื่อไหร่ |
